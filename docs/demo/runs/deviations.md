# Repeat runs: deviations from the procedure

The checklist, procedure, and scorer were frozen before run 1 (commit bab187c). Anything found since that changes
how a step is done is recorded here instead of editing the frozen files, and applies to every run from the one
named. procedure.md takes these in at the end of the series.

| # | Found | Applies from | Step | Deviation |
|---|---|---|---|---|
| 1 | Planning the dry run | The dry run | Before step 3 | The procedure never creates the series folders, and `Copy-Item` fails without them. Created once: `New-Item -ItemType Directory C:\sterling-runs, C:\sterling-runs-done, C:\sterling-runs-config, C:\sterling-runs-private\dry-login` |
| 2 | The dry run | Run 1 | 3, 5 | The launch command gives `--setting-sources project,local` unquoted. In PowerShell an unquoted comma makes an array, so the value isn't passed as written. Every run uses the quoted form: `--setting-sources "project,local"`. (The dry run's `/status` showed "Shared project settings" only.) |
| 3 | The dry run | Run 1 | 13 | The review also checks the audit's "Refused tool calls" for any refused read of the run's own files: its folder, Claude Code's temporary folder, or its saved tool outputs under `C:\sterling-runs-config\projects\`. Any such refusal goes at the top of the review's summary, before the headline results. The dry run never tried a read of a saved tool output, so the first runs are where it would show. The review prompt for step 13 adds: `Also apply docs/demo/runs/deviations.md.` |
| 4 | Run 1, step 6 | Run 1 | 6 | The process list can show `sterling-mcp.js` processes from other Claude sessions that started before the user-scope registration was removed. Step 6 passes if the run's own `claude.exe` started only `./mcp/server.js` (look up each Node process's parent). The step also checks that no other local server is listening (for example, a `vite preview` of a calibration copy, which a run could fetch over localhost); any found is stopped before step 7, and the run's private folder gets a note. In run 1, two calibration preview servers left over from planning were stopped before the request was pasted. From run 2, before the request is pasted: confirm nothing else is listening on localhost (no preview from an earlier run, the Figma desktop app closed: it serves a local MCP server on port 3845), and save the listening ports in the run's private folder as `ports.txt` |
| 5 | Run 1, steps 7–8 | Run 1 (wording only) | 6–9 | The procedure says "the session" and "PowerShell A" for the same window, so step 7 read as if only the clipboard command was to be sent. Meaning, unchanged: the request is copied to the clipboard in window B and pasted into the Claude Code session running in window A, as its first message. Step 8 needs no action when the session asks nothing; `replies.txt` then says `none`. To reword at the end of the series: name the window every time ("in window A, in the Claude Code session") |
| 6 | Run 1, step 13 | Run 1 | 13 | **Overriding a scorer result.** The reviewer may override a scorer result only when the evidence shows the scorer read the wrong region. The scorer's result and the reason stay in the row's evidence in `results-reviewed.csv`, and every override is flagged at the top of the review's summary, before the headline results. In run 1, NUM-upb went from fail to pass: the scorer read the first `<aside>` on the page, which was the run's filter panel, and the summary showed $42.6M and $50.0M |
| 7 | Run 1, step 13 | Run 1 | 13 | **Theme and density set before the app loads.** For SCREEN-theme and SCREEN-density, the reviewer also sets `data-theme="dark"` on `<html>` and `stl-density-compact` on `<body>` before the app loads (a Playwright init script), then loads the screen. Each check fails if the screen doesn't come up in that mode (Dark; Compact row height), and the owner rule applies. The scorer sets both after load, so it can't see a screen that overrides them. In run 1 both failed: the run's own Demo settings removed them when the app started, the cause of the October 14 session's correction (c) |
| 8 | Run 1, step 13 | Run 1 | 13 | **STATE-error, "Retry recovers".** Pass if Retry runs the load again (the loading state shows) and the screen recovers once the run's failure setting is turned off. Fail if Retry does nothing, or if recovery needs a page reload |
| 9 | Run 1, step 13 | Run 1 | 13 | **The review's summary also gives** the run's duration (from the request to the final list, by the transcript's timestamps), the number of MCP calls by tool (distinct tool calls; the audit counts repeated transcript records twice), and any fixed replies sent (from `replies.txt`) |
